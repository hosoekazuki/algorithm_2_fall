# Q-gram 索引による候補抽出 (q=3)

このフォルダでは、文字列データベースから 3-gram (q=3) を用いた索引を作成し、クエリ文字列と共有する q-gram 数に基づいて候補行を高速に抽出する検索ツールを提供します。現状の検索は q-gram フィルタのみを実装しており、編集距離による再検証は行いません。

## ファイル構成
- prep_X.c: データベース `db_*` から 3-gram のポスティング索引を生成し、標準出力にバイナリで書き出し
- search_X.c: クエリファイルと索引バイナリを読み込み、各クエリ行に対して候補行をビットベクトルで出力
- db_1, db_2, db_3: 文字列データベース (各行 英大文字 A〜J を想定)
- query_1, query_2, query_3, query_sub: クエリ文字列 (各行)
- index.bin: 生成された Q-gram 索引 (標準出力のリダイレクトで作成)

## ビルド手順 (Windows, GCC 推奨)
Git Bash / MSYS2 / MinGW 環境などで以下を実行します。

```bash
cd grpwk2025
# 索引作成ツール
gcc -O2 -o prep_X.exe prep_X.c
# 検索ツール
gcc -O2 -o search_X.exe search_X.c
```

## 使い方
1. 索引の作成 (例: `db_1` を対象)
  - `prep_X` は索引を標準出力に書き出すため、ファイルに保存するにはリダイレクトします。
  ```bash
  ./prep_X.exe db_1 > index.bin
  ```

2. 検索の実行 (例: `query_sub` と `index.bin` を使用)
  - 引数の順序に注意: 第1引数が「クエリファイル」、第2引数が「索引バイナリ」です。
  ```bash
  ./search_X.exe query_sub index.bin
  ```
  - PowerShell / CMD の場合:
    ```powershell
    .\prep_X.exe db_1 > index.bin
    .\search_X.exe query_sub index.bin
    ```

## 出力形式
- 各クエリ行に対し、データベース行数に相当する長さのビットベクトル文字列を 1 行出力します。
  - `'1'`: 共有 3-gram 数が閾値 `THRESH` (既定 4) 以上の候補
  - `'0'`: 閾値未満 (候補外)
- 現行の実装では所要時間の表示や編集距離の再検証は行っていません。

## 理論背景 (Q-gram フィルタ)
- 文字種は 'A'〜'J' の 10 種を想定し、`gram_id(s) = (s[0]-'A')*100 + (s[1]-'A')*10 + (s[2]-'A')` で 3-gram を `0..999` に符号化します。
- 検索アルゴリズム:
  1. クエリの 3-gram を列挙し、各 3-gram のポスティングを走査して候補行の出現カウントを増やす。
  2. 共有 3-gram 数が閾値 `THRESH = 4` 以上の行のみを候補として出力 (フィルタ)。
- 閾値の根拠: 編集距離が `≤ k` のとき、共通 q-gram 数は少なくとも `L - q + 1 - k*q` 以上になります。
  - 例: `L=15, q=3, k=3` なら `15 - 3 + 1 - 3*3 = 4` で `THRESH=4` は妥当。

## 注意事項・Tips
- 入力形式は固定長 15 の行を想定しています。異なる長さ・文字種の場合はコード中の定数と `gram_id()` のロジックを合わせて変更してください。
- 大きな `db_*` や `query_*` を使う場合は、I/O がボトルネックになる可能性があります。SSD・十分なメモリでの実行を推奨します。
- 出力の整形やタイム計測のフォーマットは必要に応じて変更可能です。
