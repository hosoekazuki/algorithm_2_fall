# Q-gram 索引と近似検索 (L=15, q=3)

このフォルダでは、長さ 15 の文字列データベースから 3-gram (q=3) を用いた索引を作成し、クエリ文字列との編集距離が 3 以下かどうかを効率よく判定する検索ツールを提供します。

## ファイル構成
- prep_X.c: データベース `db_*` から 3-gram の索引 `index.bin` を生成
- searchX.c: 索引 `index.bin` を用いて、`query_*` の各行に対して一致(編集距離 ≤ 3)の有無を判定
- db_1, db_2, db_3: 文字列データベース (各行 長さ15, 英大文字)
- query_1, query_2, query_3, query_sub: クエリ文字列 (各行 長さ15)
- index.bin: 生成された Q-gram 索引 (prep_X 実行後に作成)

## ビルド手順 (Windows, GCC 推奨)
Git Bash / MSYS2 / MinGW 環境などで以下を実行します。

```bash
cd grpwk2025
# 索引作成ツール
gcc -O2 -o prep_X prep_X.c
# 検索ツール
gcc -O2 -o searchX searchX.c
```

## 使い方
1. 索引の作成 (例: `db_1` を対象)
   ```bash
   ./prep_X db_1
   # 実行後、index.bin が生成され、所要時間が表示されます
   ```

2. 検索の実行 (例: `db_1` と `query_sub` を使用)
   ```bash
   ./searchX db_1 query_sub
   # 各クエリ行に対する結果を 0/1 で出力し、最後に所要時間を表示します
   ```
   - PowerShell / CMD の場合:
     ```powershell
     .\prep_X.exe db_1
     .\searchX.exe db_1 query_sub
     ```

## 出力形式
- searchX: 各クエリ行に対し、マッチ(編集距離 ≤ 3)なら `1`、そうでなければ `0` を連続して標準出力に出し、改行後に「所要時間: … 秒」を表示します。
- 文字化けする場合は端末の文字コードを UTF-8 に設定してください。

## 理論背景 (Q-gram フィルタ + 編集距離)
- パラメータ: 文字列長 `L=15`, q-gram 長 `q=3`, 許容編集距離 `k=3`。
- 文字種は 'A'〜'J' の 10 種を想定し、`gram_id(s) = (s[0]-'A')*100 + (s[1]-'A')*10 + (s[2]-'A')` で 3-gram を `0..999` に符号化します。
- 索引構造: 1000 個の 3-gram それぞれにポスティングリスト (登場する行IDの配列) を保持します。
- 検索アルゴリズム:
  1. クエリの 3-gram を列挙し、各 3-gram のポスティングを走査して候補行の出現カウントを増やす。
  2. 共有 3-gram 数が閾値 `THRESH = 4` 以上の候補のみ、編集距離による検証を行う。
  3. 編集距離 (動的計画法; `edit_distance()`) が `≤ 3` なら一致とみなす。
- 閾値の根拠: 編集距離が `≤ k` のとき、共通 q-gram 数は少なくとも `L - q + 1 - k*q` 以上になります。
  - 本ケースでは `15 - 3 + 1 - 3*3 = 4` なので `THRESH=4` は妥当です。
- 計算量の見通し:
  - フィルタ段階はポスティングの合計長に比例し、編集距離は候補数×`O(L^2)` です。
  - フィルタで大半を除外できるため、総合的に高速化されます。

## 注意事項・Tips
- 入力形式は固定長 15 の行を想定しています。異なる長さ・文字種の場合はコード中の定数と `gram_id()` のロジックを合わせて変更してください。
- 大きな `db_*` や `query_*` を使う場合は、I/O がボトルネックになる可能性があります。SSD・十分なメモリでの実行を推奨します。
- 出力の整形やタイム計測のフォーマットは必要に応じて変更可能です。
