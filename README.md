# Q-gram 索引＋編集距離 ≤3 の検索 (L=15, q=3/4)

このフォルダでは、文字列データベースから 3-gram と 4-gram の索引を作成し、クエリとの共有 q-gram による候補抽出の後に編集距離 (≤3) の検証を行う検索ツールを提供します。

## ファイル構成
- [grpwk2025/prep_X.c](grpwk2025/prep_X.c): データベース `db_*` から 3-gram と 4-gram のポスティング索引＋DB本体をバイナリで標準出力へ書き出し
- [grpwk2025/search_X.c](grpwk2025/search_X.c): クエリと索引バイナリを読み込み、候補抽出後に編集距離 ≤3 の判定を行い、各クエリ行に対し 0/1 を出力
- [grpwk2025/db_1](grpwk2025/db_1), [grpwk2025/db_2](grpwk2025/db_2), [grpwk2025/db_3](grpwk2025/db_3): 文字列データベース (各行 英大文字 A〜J, 長さ 15 を想定)
- [grpwk2025/query_1](grpwk2025/query_1), [grpwk2025/query_2](grpwk2025/query_2), [grpwk2025/query_3](grpwk2025/query_3), [grpwk2025/query_sub](grpwk2025/query_sub): クエリ文字列 (各行)
- `index.bin`: 生成された索引＋DB (標準出力のリダイレクトで作成)

## ビルド手順 (Windows, GCC 推奨)
Git Bash / MSYS2 / MinGW 環境などで以下を実行します。

```bash
cd grpwk2025
# 索引作成ツール
gcc -O2 -o prep_X.exe prep_X.c
# 検索ツール
gcc -O2 -o search_X.exe search_X.c
```

## 使い方
1. 索引の作成 (例: `db_1` を対象)
   - `prep_X` は索引を標準出力に書き出すため、ファイルに保存するにはリダイレクトします。
   ```bash
   ./prep_X.exe db_1 > index.bin
   ```

2. 検索の実行 (例: `query_sub` と `index.bin` を使用)
   - 引数の順序に注意: 第1引数が「クエリファイル」、第2引数が「索引バイナリ」です。
   ```bash
   ./search_X.exe query_sub index.bin
   ```
   - PowerShell / CMD の場合:
     ```powershell
     .\prep_X.exe db_1 > index.bin
     .\search_X.exe query_sub index.bin
     ```

## 出力形式
- 各クエリ行に対し、`'1'` または `'0'` を 1 文字出力します。
  - `'1'`: 候補抽出後、編集距離が 3 以下の一致が少なくとも 1 件存在
  - `'0'`: 一致なし
- すべてのクエリ行の判定後に改行が 1 回出力されます。

## 索引フォーマット (index.bin)
- 書き出し順 (いずれも 4 バイトの `uint32_t` を基本単位):
  1. `N`: データベース行数
  2. 3-gram 部 (サイズ `G3SIZE=1000`): 各 `g` について `df3[g]`、続けて `df3[g]` 個の行ID配列
  3. 4-gram 部 (サイズ `G4SIZE=10000`): 各 `g` について `df4[g]`、続けて `df4[g]` 個の行ID配列
  4. DB 本体: 各行 `L+1` バイトの文字列 (`N` 行)
- 3-gram ID: `(s[0]-'A')*100 + (s[1]-'A')*10 + (s[2]-'A')` → `0..999`
- 4-gram ID: `(s[0]-'A')*1000 + (s[1]-'A')*100 + (s[2]-'A')*10 + (s[3]-'A')` → `0..9999`
- エンディアンは実行環境依存 (通常はリトルエンディアン)。同一環境での生成・検索を想定。

## アルゴリズム概要
- 候補抽出: クエリから 4-gram を列挙し、`df4` の小さい順 (希少な 4-gram から) にポスティングを走査して候補集合を作成 (`MAXCAND=60000` で上限)。
- フィルタ強化: 候補に対してクエリの 3-gram 共有数をカウントし、`TH3=4` 以上のもののみ検証対象。
- 検証: `edit_distance_le3()` による編集距離 DP を実行し、距離 ≤3 なら一致と判定。

## 注意事項・Tips
- 入力は英大文字 `'A'`〜`'J'` のみを前提にしています。その他の文字を含むと gram ID が範囲外になり未定義動作となるため、必ず `'A'`〜`'J'` のみを使用してください。
- データベース・クエリの各行は長さ `L=15` を想定しています。短いクエリ行は自動的に `'0'` と判定されます。
- データベース行数は `MAXN=1000000` 以下を想定しています。超える場合は定数を調整して再ビルドしてください。
- 大きな `db_*` や `query_*` を使う場合は I/O がボトルネックになり得ます。SSD と十分なメモリでの実行を推奨します。
